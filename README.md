# LineOcrSearch

鼠标停在屏幕文字上，就在指定文件夹里把这段话搜出来。Windows 10/11 x64，单 exe，免安装，全离线。

## 用法

1. 双击 `LineOcrSearch.exe`。首次启动会在旁边新建 `LineOcrSearchData\` 并释放 OCR 运行时与模型（约 16.5MB），之后不再重复。
2. 点「设置」，把搜索文件夹改到你放资料的地方。
3. 鼠标停在任意文字上约 0.5 秒，自动取「鼠标所在行、鼠标右侧」最长的一段纯文字并搜索。右侧没有文字、或离文字太远，都不会硬取；鼠标放在行首左边也可以。
4. 结果双击用默认程序打开；`↑` `↓` 选中、`Enter` 打开、`Ctrl+C` 复制。长句按窗口宽度自动折行完整显示，拖动窗口大小即时重排。

输入框显示实际取到的那段纯文字。数字、标点、引号等 OCR 容易认错的符号会被当作分隔符去掉，取其中最长的一段去搜索。可直接改，**多个关键词用空格隔开，全部命中才算**。

## 键盘与右键

| 操作 | 效果 |
|---|---|
| 输入框 `Enter` | 搜索 |
| 输入框 `↓` / `↑` | 跳到结果列表，选中第一条 / 最后一条 |
| `↓` / `↑` | 选中下一条 / 上一条（滚动跟随） |
| `PageUp` / `PageDown` | 列表翻页 |
| `Home` / `End` | 滚到顶 / 底 |
| `Enter` | 打开选中的文件 |
| `Esc` | 取消选中 |
| `Ctrl+C` | 复制命中行 + 路径 + 行号 |
| `Ctrl+Shift+C` | 只复制文件路径 |
| `Ctrl+F` | 回到搜索框并全选 |
| `Ctrl+Enter` | 加载更多（结果被「结果条数」截断时） |
| `F5` | 按当前关键词重搜 |
| `Tab` / `Shift+Tab` | 输入框 → 搜索 → 设置 → 结果列表 循环 |
| 右键点结果卡片 | 菜单：打开文件 / 打开所在文件夹 / 复制命中行 / 复制文件路径 / 复制「路径 · 第 N 行」 |

设置窗口：`Tab` 切换控件，`Enter` = 确定，`Esc` = 关闭。滚动条支持按住拖动，也可直接点轨道跳转。

## 设置

搜索文件夹 · 停留多久取词（0.2–1 秒）· 自动取词 · 取词后自动搜索 · 取词方式（智能 / 自动 / 总是 UIA / 总是识别图片）· 搜不到时逐字回溯 · 同时搜 Word/Excel · 前后文详略 · 结果条数 · 缓存上限（64–512 MB）。点「确定」保存。

取词方式的区别：**智能**用 OCR 定位、UIA 校正文字，两者互相补充；**自动**两条都试，按效果选一条整体更好的；**总是 UIA** / **总是识别图片**只用单条通道，适合已知某一通道更可靠的程序。

缓存是「按文件夹预建」的：在设置里点「浏览」选完文件夹，或直接点「生成缓存」，就会立刻把该文件夹里支持的文件解析进缓存（已有且未改动的直接复用），建立过程中可以点「停止」。目录里没有支持的文件时不会产生缓存，并弹窗提示。缓存上限只管磁盘，超出后按写入时间从旧到新淘汰。

缓存失效条件：源文件的大小或修改时间变了、或程序内置的「解析器版本」升级了（修复提取 bug 后自动换新版），对应缓存会在下次搜索时自动重建，不需要手动清理。

## 搜索范围

42 种文本后缀 + docx / docm / xlsx / xlsm 正文，以及 Word 97-2003（`.doc`）、Excel 97-2003（`.xls`）正文——老格式由程序自己解析 OLE 复合文档，**不依赖装 Office / LibreOffice**。文本单文件 ≤ 2 MB，Office ≤ 16 MB。

不支持：加密文档、Word 6.0/95 及更早、Excel 5.0/95、WPS 私有格式（`.wps` / `.et`）；这些仍只按文件名匹配。

## 多文件结果怎么排

搜索会**先把每个文件的命中数统计完，再分配显示名额**：每个有命中的文件保底 1 条，剩余名额逐轮分给还有剩余命中的文件（命中多的文件分到的更多）。所以一个 100 处命中的大文件不会把「结果条数 50」吃光，其它文件的命中也能露出来。

列表按文件分组：组间按命中数降序（同数按路径），组内按行号升序。状态栏显示 `命中 N 条 · M 个文件 · 显示 K 条`；超过显示名额的命中留在暂存区，点列表底部的「**还有 X 条命中 · 点击加载更多**」卡片（或按 `Ctrl+Enter`）每次追加 50 条。单文件命中数上限 100 行。

## 构建

需要 zig 0.17.0。`build.bat` → `dist\LineOcrSearch.exe`（约 17.5MB，已内嵌 `res\` 下三个资源）；`tests\run_tests.bat` 跑测试。

源码树里 `res\` 只是打包输入，`LineOcrSearchData\` 是 exe 首次运行才生成的，两者不是一回事。

## 注意

数据都在 exe 旁的 `LineOcrSearchData\`：`config.ini`（设置）、`cache\store.bin`（文档提取缓存，单文件存储库，默认上限 64MB，可在设置里改到 512MB）。截图、识别结果、日志都不落盘。

缓存是「一个文件装全部文档正文 + 内存索引」：搜索时只开一次文件，2000 份文档从「每次 1.2 秒」降到热启动十几毫秒。旧版本留下的 `cache\*.cache` 会在首次运行新版本时自动清掉。
